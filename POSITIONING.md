# Positioning

## Core Idea

A Russian-language editorial edition of `AI Engineering Hub` for practical builders.
Not just a catalog of 90+ folders, but a filter: what to launch first, what is worth your time, what can be run locally, and what should be skipped unless you already know why you need it.

## One-Line Positioning

`AI engineering for Russian-speaking vibe coders and developers: curated projects, local-first paths, and honest setup notes.`

## Short Repo Description

`Curated AI engineering projects for RU builders: RAG, agents, MCP, local LLMs, and practical launch paths without catalog overload.`

## README Opening Angle

Use this tone in the main README:

- We reduce choice overload.
- We explain why each project matters.
- We mark cost, complexity, and likely setup pain.
- We adapt recommendations for local and RU-friendly tooling.

## Content Pillars

- Local-first AI: Ollama, open-weight models, local vector stores, minimal hosted dependencies.
- Practical shipping: build a useful prototype in one evening, not a theoretical stack diagram.
- Honest curation: some projects are educational but not worth a beginner's time. Say that directly.
- Tooling reality: show substitutions for services that are expensive, region-sensitive, or unnecessary.
- Builder outcomes: Telegram bot, document chat, OCR workflow, research assistant, code agent, MCP integration.

## What To Avoid

- Positioning it as a pure translation project.
- Claiming everything is beginner-friendly.
- Over-indexing on model hype instead of use cases.
- Promoting expensive or fragile demos without warning.
- Turning the repo into a link dump again.

## Best Next Step After This Branch

Pick 10 to 15 flagship projects and add full Russian cards for them first.
That will create actual editorial gravity and make the fork feel intentional instead of merely repackaged.
